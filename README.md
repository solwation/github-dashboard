# Issueflow

Track your AI agents’ work through GitHub issues.

**[Open Issueflow →](https://solwation.github.io/github-dashboard/)**

One view of what your agents plan, work on and complete across your repositories. Follow AI agents that use GitHub issues as their work queue, or track issues you handle yourself. Backlog sorts by priority, active work shows elapsed time, and Closed keeps the last 30 days in view.

- **Public repositories without a key:** choose **Follow public repositories** on the welcome screen, add `owner/repo` names or GitHub repository URLs, then choose **Show overview**. Public mode supports cards, lists, filters, local rules, estimates and available REST statistics. Its catalog, preferences and whole repository snapshots are encrypted in a separate local profile; saved account credentials and private content remain separate. Reload reuses snapshots for up to 24 hours without API requests, and changing selection loads only missing or expired repositories. The content cache keeps at most 100 complete repositories within 4 MiB; oversized or incomplete repositories are fetched normally. Failed refreshes retain the last successful data and sync time, without extending its age. Closed issues still leave the view after 30 days. Refresh manually from the repository status or with Ctrl/Cmd+R/F5; public mode does not poll or register background collection. GitHub allows 60 anonymous REST requests per hour per IP, so work-start history uses at most two shared event pages per repository, and missing history stays unknown. GraphQL-only details stay hidden. Leave the public workspace to return to sign-in.
- **Find issues:** combine the global text filter with independent filters per repository; search titles, issue numbers and labels, and clear each repository filter separately. On phones a collapsed repository hides its search field; the query is kept and applies again when expanded.
- **Split or combine:** Split by repository is on by default; uncheck it for one board covering every selected project. Split lanes are headed by their repository; on the combined board each card shows a repository badge in a contrasting palette color matching the sidebar dot. The combined board is filtered by the main search alone; per-repository searches apply only in the split view and keep their values. Color assignments stay stable when sorting or changing the selection, are saved per account and follow QR sync alongside the view choice. Combined columns use the global card limit.
- **Cards or list:** One Cards/List switch at the far right of the board toolbar (after Split by repository on narrow screens) shows a compact row per issue with number, title, status, priority, main labels and time. It applies to every repository in the split view and to the combined board, which adds a repository column with name and color. In combined cards and lists, repository labels omit the owner only when all selected repositories share that owner (case-insensitively), even if issue filters hide some repositories; full names remain in tooltips and screen-reader text. Filters, column limits, Show more, timeout and movement markers work in both modes. Movement/New and timeout markers have separate reserved places before status, vertically centred, with a separate space for new comments so appearing or reading them does not change row height or column positions. Desktop labels share one clipped line, with full text in their tooltips and expanded card, so long labels cannot push the timeout onto another line. Lists at least 850px wide show a comments icon and count directly on each row; opening it uses the existing comments dialog without expanding the row. Phone rows in portrait and landscape use two compact lines: number, priority, points and title above repository/activity markers and separate time fields. Main labels and details remain in the full card popup. Narrower desktop lists retain comments in the expanded details. Short touch viewports keep the compact phone layout even above the portrait width breakpoint. On desktop and tablet, clicking a row (or Enter/Space on its title) expands all card details in place with the description already open; on phones, tapping a row opens the full card in a popup dialog. Expanded descriptions keep readable line lengths; wide rows can place standalone images on the right. The issue number with ↗ is a separate link that opens the issue on GitHub in a new tab. Expanded rows are not saved. The choice switches instantly without refetching, is saved in the encrypted account settings and follows QR sync. Earlier per-repository choices migrate automatically: with Split by repository off the combined board's choice wins, otherwise List applies when more than half of the selected repositories used it; older QR codes are read the same way. Story-point tooltips show estimated total time when sufficient filtered repository history exists. With that history and a known start, in-progress cards show remaining time and a compact elapsed-time bar at the bottom right; list rows keep remaining time in their rightmost column, separate from elapsed time, including on phones. Backlog uses the same column for an italic total estimate with ≈ when sufficient history exists. Overdue estimates are clearly marked. Closed rows and cards show observed work-start-to-close duration when known, with an up/down arrow against the point-based estimate calibrated from other recent closures; creation age never substitutes for work time. Closed list rows use that same rightmost column for actual work duration and its comparison arrow, separate from the closing date; full descriptions remain in tooltips and the card.
- **Unread activity:** The Overview sidebar badge counts unseen recent events across selected repositories, including new comments and movement, using the existing two-minute activity lifetime and encrypted read acknowledgements. Search, row limits and collapse do not change it; hidden coordination issues and pull requests are excluded.
- **Your layout:** reorder projects, collapse repositories and set how many cards each column shows. On mobile, open Settings → Reorder repositories to drag handles or use up/down buttons; the order saves immediately and stays consistent with the desktop sidebar. Expanding a collapsed repository resets Show more in all its columns to the configured global or repository limit, in both Cards and List mode. Selecting a collapsed repository in the sidebar expands it automatically and briefly outlines its container; reduced motion uses a static outline. Confirmed repository selections appear immediately; new projects show loading while existing data stays visible.
- **Issue hierarchy:** parent cards show a compact closed/total badge; sub-issues link to their parent, including across repositories. Expanded card and list details group the closed/total count, progress bar and each sub-issue with Backlog, In progress or Closed status below the description, including repository-specific label rules. Available progress remains visible when individual sub-issues are inaccessible. The list loads on demand through paginated REST, works for public repositories without a key and shares a bounded ten-minute cache. Relations stay hidden when unavailable. Counts come from GitHub and are independent of dashboard filters.
- **The context you need:** read issue descriptions, comments shown newest first with live relative timestamps for the first seven days (exact time on hover), and closing commit details, including embedded images linked to GitHub repository files. Comments show compact clickable thumbnails for Markdown images and direct HTTP(S) image links (PNG, JPEG, GIF, WebP, AVIF, SVG, BMP and ICO, including query strings and GitHub blob links, plus GitHub attachment URLs without extensions). The image dialog supports fit (enlarging or shrinking the complete image to the available area, including after resizing), original size, zoom buttons, Ctrl+wheel zoom, dragging and touch pinch/pan; Escape returns to the comment. Direct links stay available when a preview cannot load.
- **Ready when you return:** encrypted local sign-in and content cache, with automatic GitHub updates. Repositories with active work are checked every 15 seconds with one conditional request each, so unchanged checks do not use your GitHub rate limit and do not rewrite the encrypted cache; hovering (300 ms), focusing or clicking a repository in the sidebar refreshes just that repository when its last successful refresh is over 5 minutes old, at most once per minute, never in parallel with another refresh and silently skipped while rate-limited or near the quota; sub-issue relations reload when an issue changes, on a full refresh or after 10 minutes. Account settings are encrypted per account on this device and come back when you sign in again after logout. Signing out returns navigation to Overview, so Statistics opens directly on the first click after signing back in.
- **Optical sync:** transfer account, chosen settings and view in either direction using a local QR code. Scan from the QR popup or Settings while signed in; browser permissions and read markers stay on each device. Codes carry a compact binary profile as QR numeric digits, keeping them small enough for laptop webcams; older base64 codes remain readable. A link or scanned code for a different account never replaces a saved sign-in without a confirmation naming both accounts; canceling keeps the saved session.
- **At your desk or on your phone:** responsive columns, keyboard controls, Swedish and English.
- **Light or dark:** Settings → Theme offers Auto (default), Light and Dark. Auto follows your device’s color scheme live; a manual choice overrides it. The choice is saved per browser, survives reload and logout/login, and applies before the first paint so dark mode never flashes light. Colors are CSS tokens redefined for dark mode, with readable text, charts and repository colors.
- **Plan from the overview:** Open issues and In progress summary badges show summed estimated story points and the same calibrated remaining-time horizon as the board columns. Counts and points share the current global and repository filters. Repositories run in parallel; the slowest determines the forecast. Time for a partly calibrated selection is labelled with its repository coverage, and missing history leaves the time hidden. Estimate clocks stay inside the badges and pause in Statistics.
- **Statistics loading coverage:** The shared progress panel shows an activity spinner throughout source checks and commit loading, with a percentage bar once the commit workload is known; its subtle green styling separates progress from supporting details. A thin track below each chart shows the confirmed loaded span for its selected metrics while collection runs. Sorted update pages and completed commit diffs extend it; unordered issue events require their full list, and sparse old activity alone never proves coverage. The track follows the chosen period, uses existing batched previews and disappears after collection.
- **Explore activity:** Overview and Statistics reuse the same repository card frame and identity heading, with an avatar, owner, description, private badge and accessible collapse control; each view supplies its own controls and content. Statistics stacks the repositories selected in the sidebar in board order, with aligned, equally sized repository filter fields and shortened section names when all selected repositories share one owner (full names remain in tooltips), with issue, commit, code-change and pull-request charts from the latest 30 local calendar days. Only the first repository is expanded initially. Collapse choices persist with the account’s encrypted settings across reloads; collapsed repositories send no statistics requests, including background collection. Expanding a repository loads it on demand, Refresh updates only expanded repositories, and collapsing during collection stops further requests after any already in flight. Filters and chart choices remain intact; clicking a sidebar link expands, loads and scrolls to that repository without leaving Statistics. In both Overview and Statistics, activating the same focused sidebar repository again toggles its collapsed state; in the combined board it toggles the repository’s settings section. One compact time row applies to every repository, with the period on the left and interval/resolution dropdowns on the right: presets (8 hours to 30 days) keep the From/To pickers hidden; choosing Custom reveals local date-and-time pickers filled with the selected window, a period label shows the displayed dates and duration, and the resolution can range from minutes to days (30-day windows require at least six-hour resolution). The shared time zone appears beside your account in the top bar, rather than after normal Statistics timestamps (ambiguous autumn times retain an offset). Displayed times follow your browser’s time zone and daylight-saving changes; saved windows and QR sync preserve the same absolute instants across devices. Each repository groups its totals into Issues, Pull requests and Code for that same period; the totals are buttons that choose which lines the chart shows, in matching colours. Label and contributor filters sit in each repository heading with removable chips, and the contributor and label breakdowns start collapsed on all screens. Available badges and charts fill in gradually while statistics are loading, and refreshes retain prior data until new results arrive. Intermediate updates are batched across repositories; only finished collection results are saved to the encrypted cache. Loading feedback stays brief and repeats no period details: a spinner with the source checks, then, once the commit-detail workload is known, completed commits and a percentage; approximate time remaining appears only after at least three fresh detail results and two seconds of measured throughput. This progress is never persisted. Time controls refresh local calendar boundaries after midnight and queue one fresh collection behind any request already running. Unavailable metrics stay hidden; bounded API collection is marked when incomplete, including a coverage note for the selected chart metrics. Event pagination follows up to 100 pages, and code metrics include every collected non-merge commit (up to 300 freshly listed or 600 with reused history). Busy repositories therefore retain older activity beyond the former 500-event and 60-diff cutoffs. The first load can need more requests; immutable commit details are reused on later refreshes. Charts fill their panels while keeping lines, points and labels at a consistent size. Hover a chart to read every series at the selected point in a compact popover; touch and a keyboard slider (shown only while focused) provide the same values without a permanent chart-time row. Encrypted statistics restore immediately on return (up to 10 repositories, 8 MiB, seven days). While you stay on the board, statistics are also collected quietly in the background so Statistics opens without loading: starting 30 seconds after sign-in, one repository at a time in idle moments, for up to 10 expanded repositories within the same 8 MiB cache. Collection pauses in hidden tabs, offline, with Data Saver, reduced-data preference or low battery, near the GitHub rate limit or after Retry-After, while the board syncs, shortly after you type, click or scroll, and while Statistics is open. Complete commit history reuses historical days and overlaps the previous last UTC day; immutable SHA diffs are reused. Issues, events and PRs are revalidated, and full commit membership is checked every seven days or with Refresh. Issues reuse the board's lists when they were confirmed within the last five minutes, and other lists revalidate with ETags, so unchanged data costs no rate limit.
- **Active projects:** the Repositories card shows how many selected projects have Backlog, In progress or issues closed in the last 30 days, independently of text filters.
- **New work:** issues created in Backlog after startup get a green “Created in backlog” marker until read or expired. Returning work keeps its separate movement marker.
- **See changes:** Overview counts and their sub-values briefly highlight increases and decreases (sub-values float a short +1/−1), with a daily count of loaded issues closed today in your local timezone.
- **Issue sizes:** cards and list rows show estimated story points as “≈ 3 SP”, including combined boards and phones. They use the same local 1/2/3/5/8/13 sizing as column forecasts, independently of available timing history; the tooltip explains the approximation. Expanding a desktop list row keeps the badge on its summary; phone popups show it on the full card.
- **Column estimates:** the In progress and Backlog headers show a compact forecast such as "≈ 25 min left" and "≈ 3 h 10 min". Calibration uses the most recent 30 eligible issues closed within a rolling 30-day window, with at least three known positive In progress-to-closed durations. Each issue receives rough points on a 1/2/3/5/8/13 scale: an unambiguous explicit points label wins, otherwise cleaned title/body vocabulary, distinct scope items and bounded risk signals provide a local heuristic. Repeated boilerplate, pasted code and logs do not automatically imply more work; these points are not measured complexity. Before calibration, durations per story point above four times the raw window’s median are excluded as suspected interrupted runs; ordinary overruns and proportionately larger issues remain. At least three samples must remain. The retained samples determine time per point, typical duration and historical parallelism, including closed-issue comparisons (which exclude the issue itself before filtering). Actual closed-issue durations remain visible. The repository median duration per point sets each issue’s expected time. In progress subtracts elapsed time and shows the longest remaining forecast; Backlog adds its point total × time per point ÷ measured parallelism. Combined boards show the slowest repository. Tooltips explain the points, calibration window and rate. The header’s own clock updates elapsed time and ages out expired history; nothing is shown without enough usable evidence.
- **Spot stalled work:** Settings can disable estimate-based warnings or set an allowed overrun from 0–1000% (default: enabled, 25%). In-progress work is flagged only after its calibrated total estimate plus that tolerance, with a reliable start and sufficient history. Warning text on cards and list rows uses the estimate; foreground and background notifications follow the same rule. Settings and calibration changes establish a silent notification baseline, preserving one notice per work period. Older fixed-minute preferences migrate to the new defaults; the new choices are encrypted per account and follow QR sync. Time labels update on their own: seconds only while shown on screen, and not at all in hidden tabs or while Statistics is open, so large boards stay light.
- **Hear progress:** open a repository’s properties to enable its notifications for distinct sounds when work starts, closes, becomes blocked or returns to Backlog. Mute notification sounds separately in Settings while keeping repository and browser notifications; the choice is saved per account. Audio resumes after interacting with the dashboard; browsers may delay background updates.
- **Notifications while closed:** the installed app in Chrome or Edge can notify you about closed, started, returned, reopened and timed-out issues in repositories that are selected with notifications on, even when no window is open. See [limitations](#background-notifications).

- **Project details:** the whole sidebar license card opens LICENSE in a new tab; license and version icons sit at the right edge.

Issueflow reads GitHub. Make issue changes on GitHub; private content stays in your browser's encrypted storage.

## Background notifications

Background checks use Periodic Background Sync and work only in Chromium browsers (Chrome, Edge) with Issueflow installed as an app, signed in and with notification permission granted. Safari and iOS are not supported; other browsers notify only while the dashboard is open.

- **The browser decides when to check.** Issueflow asks for about one check per hour, but the browser chooses the interval from its own engagement and battery heuristics, often several hours apart and never guaranteed. Checks may stop entirely while the device sleeps or the app is rarely used.
- **The first check is silent.** It records a baseline; later checks notify only about changes since the previous check. Checks older than 24 hours start a new silent baseline, so stale changes are not announced. An open, visible app window announces changes itself and the background check only updates its baseline.
- **Everything stays on the device.** There is no server, webhook or push service: the browser wakes the service worker, which reads the token and settings from the encrypted local stores, asks GitHub directly and keeps the last seen state as AES-GCM ciphertext in IndexedDB. Logout clears it with the rest of the content cache.

## Connect

Use a fine-grained GitHub token with **Issues: read** and **Metadata: read**. Add **Contents: read** and **Pull requests: read** for private closing commit details. Try the demo first—no account required.

Settings groups permissions, workflow instructions, automatic updates and QR scanning in a consistent button list. Update prompts stack their action buttons vertically and show the ten-second countdown inside Update now (10); opening a dialog pauses the countdown, while Not now defers until tomorrow. The sidebar shows whether a version check confirmed the latest version, found an update, or has not completed. The Issue workflow instructions button opens a compact popup with the full bundled Markdown in a scrollable textarea and a Copy instructions button.

Settings → GitHub permissions shows verified access and explains which features each read permission enables. A red Settings badge counts permissions with confirmed missing access that you have not viewed. Viewed notices stay acknowledged per account on this device after reload or logout/login; the permission table keeps showing the actual access results.

The sidebar shows the running version (build date and short commit) above the footer, with Release notes. When a new version is published, every open tab, visible or in the background, shows a short summary of what changed and installs it after a 10-second countdown shown in **Update now (10)**. Open dialogs pause the countdown and closing them restarts the full ten seconds. **Not now** postpones the automatic prompt until the next calendar day in your time zone (remembered on this device, also for background checks). Until the update is installed, a red (!) badge on the sidebar version opens the update view, also available from Settings → Automatic updates. Updates keep encrypted sign-in, settings and cached content; offline or failed activation keeps the current version running.

## Release notes

What's new is written per day in Swedish and English in [`src/release-notes.json`](src/release-notes.json), newest day first. Each day has a short summary and a few readable sections about user benefit, each listing the related issue numbers. Only changes published on `main` are included; no secrets or private repository content.

The build bundles the notes and also publishes `release-notes.json` next to `index.html` with the build identity (`builtAt`, `commit`). An older installed version can fetch it without a token, sign-in or AI access to show what changed since it was built; the file is always fetched from the network, never from the app-shell cache.

Keeping notes current: every published user-facing change adds to or updates that day's entry (Europe/Stockholm date) in the same commit. Merge related work into the existing sections rather than adding one line per issue or commit, and do not describe unpublished or later-replaced behavior. `tests/release-notes.test.ts` validates the file.

## Run locally

Requires Node 22.20+.

```sh
npm ci
npm run dev
```

Use Node.js 22. `npm ci` applies the version-23 jsQR compatibility correction used by optical profile sync.

Run affected tests locally before pushing; use `npm run build` for code changes. Integration pushes are allowed while work remains; GitHub Actions decides publication through a fresh issue/delta gate before building and again before deployment. Unfinished or active issues block publication; locally verified, unclaimed `needs-deploy` issues must appear in the prepared delta. If nothing has been published for 3 hours, an hourly scheduled run publishes the finished batch even while other issues are still active, so `main` only ever receives finished work. Manual deployment never bypasses the gate. Orkester watches for new issues every minute for 60 minutes after the last verified release; new completed work restarts that window. Generate the popup summary in `src/update-summary.json` from that publication’s delta against the previously deployed build (maximum 180 characters per language). Full daily notes remain available through Read more. The build rejects unresolved merge markers, including those that would otherwise render as text in Vue templates. Browser tests need a one-time `npx playwright install chromium`. Actions only builds and publishes.
