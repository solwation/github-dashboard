# Integration audit — issue #68

Date: 2026-10-16. Scope: **all 66 closed issues among #1–#67**. #52 remains open and is excluded from completed-work claims.

The audit compared each issue’s acceptance criteria with source, actual App/component/API wiring, history and later replacements. The baseline was `eaa659493c928af9ba08532cc00de2a783e6f038`; local main and origin/main matched. Fetching the deployed Pages entry confirmed the same visible merge artefacts were present in its JavaScript. A closed issue or an existing commit was not treated as proof of a working feature.

No additional deleted implementation or dropped UI connection was found beyond the defects below. At the baseline, 53 rows were present, eight deliberately superseded, one duplicate and four affected by defects. The four affected rows (#9, #46, #48, #63) represent **three distinct defects**, now repaired. Source paths/line references in the table describe the audited baseline; repair and runtime verification are recorded here.

## Findings and repairs

1. **Settings conflict and duplicate Permissions (#9/#46, introduced by the #56 integration).** Commit `ffabc90` retained literal conflict-marker lines in the Vue template and both versions of `GitHubPermissions`. Vue compiled the markers as ordinary rendered text. One of the duplicate components lacked badge-acknowledgement handlers. The repair keeps a single component with opened/closed acknowledgement wiring, preserves the timeout field and leaves workflow/QR/build controls intact.
2. **Filtered Overview feedback (#48).** Hidden issues could cancel visible issue changes in the unfiltered aggregate, suppressing an animation even though a displayed count changed. Snapshots now apply the same global/repository text filters as the displayed counts. Filter edits reset the baseline silently; real subsequent changes produce the visible delta and the correct completion/backlog color.
3. **Authenticated language persistence (#63, also relevant to #9).** A language-only edit updated the device language but did not save the account’s transferred language preference. Reload could restore the old value. The account-save watcher now observes language preference too. A signed-in language-only edit/reload regression passes.

## Prevention and verification

- `npm run build` now starts with `scripts/check-source-integrity.mjs`, rejecting ordinary and diff3 conflict-marker lines in tracked text, including Vue template text. The scanner demonstrably failed on the original Settings file and passes after resolution; two tests exercise the real command against staged temporary repositories.
- **221 logic/transport tests passed across 32 files.**
- **All 87 browser scenarios are accounted for.** The broad serial run passed 83 and exposed four stale test assumptions. The three affected files were corrected and all ten scenarios in those files passed on rerun. The product source was unchanged between those browser runs. Existing and added scenarios cover the single Permissions entry, badge acknowledgement, timeout controls, filtered opposing transitions, authenticated language-only reload, native issue hierarchy, relative/newest-first comments, QR scanning, encrypted cache/session restoration, real service-worker updates and mobile layouts.
- The stale assumptions were: counting on-demand GraphQL parent lookups as board refreshes during navigation (two widths), mutating the device language storage behind the supported Settings flow despite account preferences, and expecting no view hash after optical view transfer. The corrected assertions still protect against board refetch/document reload, lost layout/language settings and credential fragments in URLs.
- Production type checking/build passed. Final GitHub Actions/Pages deployment is verified before closing #68; deployment outcome is tracked on that issue rather than inferred from this source document.

These are source reviews and automated browser tests using controlled GitHub responses, plus actual public Pages asset verification. They do not claim a manual test with every user token, organization policy or physical audio device.
